# fix-191282e13fd7f790 — Duplicate `/start` handler causes non-deterministic behavior and CI failure

**Weight:** 0.0000 (share of project budget)
**Reward:** 0 ECHO

`src/handlers/T02.ts:8` and `src/handlers/E2T1.ts:7` both register `command("start")`. In `src/bot.ts:15-23`, composers are loaded via `readdir` and applied with `bot.use()`. `readdir` does not guarantee alphabetical order — only the first composer matching `/start` will fire (grammY stops middleware propagation when a handler matches and does not call `next()`). T02 sends `"Welcome! I am your bot assistant..."` with an inline keyboard; E2T1 sends `"Hi — I'm EchoSnap..."` (the spec-compliant message).

**Consequence:** The behavior of `/start` is non-deterministic across deployments. Both `tests/specs/T02.json` and `tests/specs/E2T1.json` test `/start` with conflicting expected text — one spec will always fail, blocking the CI test gate. Remove T02.ts's `/start` handler (replaced by E2T1.ts) or merge them into one.
